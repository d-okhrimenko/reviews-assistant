# Реалізація AI-абстракції та тестової заглушки

## Цілі

- У `Application` додано провайдер-незалежні `IAiReviewAnalyzer`, `IAiResponseGenerator` та DTO входу й результатів.
- Результати містять дані аналізу або чернетку, а також назву провайдера й моделі.
- У `Infrastructure` реалізовано детерміновані `Stub`-версії без мережевих запитів і API-ключів.
- Значення `Ai:Provider=Stub` реєструє заглушки в DI; невідомий провайдер зупиняє запуск із конфігураційною помилкою.
- Новий провайдер додається реалізаціями тих самих контрактів без змін контролерів або Angular-клієнта.
- Авторизований адміністратор може запустити Stub-аналіз із картки відгуку та одразу побачити оновлені AI-поля.
- Авторизований адміністратор може згенерувати Stub-чернетку відповіді з картки відгуку та одразу побачити її текст.

## Нотатки

- Дотримуватися `CancellationToken`; не логувати ключі та повний текст відгуку.
- Заглушка має повертати лише валідні для доменної моделі значення.
- Аналіз виконується синхронно без черг і фонових воркерів; помилка аналізатора встановлює статус `Failed`.
- Помилка генерації не змінює наявну чернетку відповіді.

## Історія

- Покращення адміністративного перегляду — локалізовано enum-значення та додано кольорові бейджі тональності й пріоритету; моделі згруповано за доменами.
- Базовий функціонал Reviews Assistant — реалізовано Web API, Angular-клієнт, PostgreSQL-міграції, JWT-автентифікацію, Swagger UI та адміністративні сценарії.
